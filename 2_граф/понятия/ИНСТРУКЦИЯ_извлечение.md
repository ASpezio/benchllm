# Извлечение понятий из элементов кодификатора (проект «SyllaBench», часть «Граф»)

Вход — JSON с полем `items`: каждый элемент содержания школьной программы (ФОП) или пункт ОГЭ/ЕГЭ:
`source_id`, `code`, `text` (текст из приказа), иногда `text_latex` (тот же текст с формулами LaTeX в `$…$` — формулы бери отсюда), `section` (раздел), `category` (для физики: content / practice — практические работы / nature — явления в природе / devices — технические устройства).

Задача — разбить каждый элемент на **понятия**: отдельные вещи, про которые можно задать вопрос и которые можно отдельно найти в справочнике. Элемент — это заголовок с перечнем тем, понятие — одна тема.

## Правила

1. **Только то, что есть в тексте.** Ничего не добавляй от себя. У каждого понятия поле `evidence` — точная подстрока из `text` (символ в символ, можно короче, но без изменений; для формул — из `text_latex`). Это будет проверено скриптом.
2. **Имя** (`name`) — нормализованное, в именительном падеже, как в школьном учебнике: «Законы Хаммурапи», «Закон Архимеда», «Удельная теплоёмкость вещества». Без кавычек-ёлочек, без точки в конце.
3. **Гранулярность.** Одно понятие = одна тема для вопроса или поиска.
   - «Царь Хаммурапи и его законы» → «Хаммурапи» (личность) + «Законы Хаммурапи» (документ).
   - «Средняя скорость при неравномерном движении» → «Средняя скорость» (величина) + «Неравномерное движение» (явление).
   - Не делай понятий из служебных слов: «значение», «роль», «особенности», «развитие», «примеры», «основные». «Значение письменности» → «Письменность».
   - Перечень через запятую — отдельные понятия: «Технические устройства: термометр, барометр» → «Термометр», «Барометр».
   - Практическая работа — одно понятие на каждую работу (тип `опыт`), имя — по смыслу работы: «Измерение плотности жидкости».
4. **Тип** (`type`) — строго из списка своего предмета:
   - История: `событие` (войны, походы, восстания, реформы, открытия), `процесс` (колонизация, распад, становление, торговля), `личность`, `государство_народ` (государства, народы, племена, общности), `место` (регионы, реки, города как места), `документ` (законы, летописи, источники), `термин` (понятия: фараон, полис, демократия, рабство), `памятник_культуры` (пирамиды, Парфенон, поэмы Гомера), `религия_верование`, `период` (только если период сам — тема: «Эллинизм», «Древний мир»).
   - Физика: `явление` (тепловое расширение, электризация, диффузия), `величина` (скорость, плотность, сила тока), `закон` (закон Гука, закон Ома, закон сохранения энергии), `модель` (материальная точка, идеальный газ), `понятие` (вещество, тело, теплопередача, электрическая цепь — всё прочее теоретическое), `опыт` (практические работы, опыты, исследования), `прибор` (технические устройства, приборы, механизмы), `природное_явление` (примеры из строк «Физические явления в природе»).
5. **Дополнительные поля** (только если это есть в тексте):
   - `formula` — формула LaTeX из `text_latex` для закона или величины: `"F_A = \\rho g V"`.
   - `date` — дата или период из текста: `"VIII–VI вв. до н. э."`, `"490 г. до н. э."`.
   - `aliases` — другие названия из того же текста: «выталкивающая (архимедова) сила» → name «Выталкивающая сила», aliases [«Архимедова сила»].
   - `role`: `"main"` — понятие, ради которого элемент написан (обычно первое в тексте или в заголовке), `"part"` — остальные.
6. Не пропускай понятия: перечисления в истории длинные (до 30 тем) — бери все.

```json

  "concepts": [
    {"name": "Хаммурапи", "type": "личность", "evidence": "Царь Хаммурапи", "role": "main"},
    {"name": "Законы Хаммурапи", "type": "документ", "evidence": "его законы", "role": "part"}
  ]}]
```
Каждый `source_id` из входа должен быть в выходе ровно один раз. После записи запусти проверку:
`python3 /home/claude/att/2_граф/понятия/check_concepts.py <вход.json> <выход.json>` — она должна вывести «OK». Если нет — исправь и запусти снова.
