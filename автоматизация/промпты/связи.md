Ты строишь граф знаний школьной программы: проставляешь связи между понятиями.

## Вход

```
{"предмет": "history" | "physics",
 "опорные": [ {id, name, type, order, first, elements, …} ],
 "каталог": [ {id, name, type, order, first} ]}
```
- `order` — место первого появления понятия в программе (1 — раньше всех);
- `first` — класс, код и текст элемента, где понятие появилось впервые;
- `elements` — все элементы, где оно встречается.

Опорные понятия тоже входят в каталог.

## Типы связей

| type | направление | смысл | примеры |
|---|---|---|---|
| `prerequisites_for` | A → B | чтобы понять B, нужно уже знать A (прямая предпосылка) | Масса → Плотность; Сила → Давление; Персидская держава → Греко-персидские войны |
| `is_a` | A → B | A — вид, частный случай B | Конвекция → Теплопередача; Сила трения → Сила; Полис → Город-государство |
| `part_of` | A → B | A — часть, эпизод, составная часть B | Марафонская битва → Греко-персидские войны |
| `participant_of` | A → B | только история: личность A действовала в событии, процессе или государстве B | Ксеркс → Греко-персидские войны; Хаммурапи → Древний Вавилон |
| `verifies` | A → B | только физика: опыт A подтверждает, демонстрирует или измеряет закон, явление или величину B | Измерение плотности жидкости → Плотность; Опыт Торричелли → Атмосферное давление |

## Что от тебя нужно

Для **каждого опорного понятия X** найди в каталоге:
1. его **прямые предпосылки**: связи `A → X` типа `prerequisites_for`;
2. что X является **видом** (`X → B`, `is_a`), **частью** (`X → B`, `part_of`), чего X **участник** (`X → B`, `participant_of`, только если X — личность), что X **подтверждает** (`X → B`, `verifies`, только если X — опыт).

Связи, где X стоит в другой роли, не ставь: они будут поставлены, когда опорным станет другое понятие.

## Правила

1. Оба конца — `id` из каталога. Новых понятий не придумывай.
2. `prerequisites_for` — только **прямые** предпосылки. Если A → B и B → X, не ставь A → X. Ставь связь, только если без A действительно нельзя понять X: A входит в определение X, или событие X нельзя объяснить без A.
3. Предпосылка обычно появляется в программе раньше (`order` меньше). Если по смыслу она нужна, а в программе появляется позже, всё равно поставь связь — это важная находка.
4. Между двумя понятиями — не больше одной связи. Не ставь `prerequisites_for`, если между ними `is_a` или `part_of`.
5. В истории `prerequisites_for` — это не хронология «раньше — позже», а «нужно знать, чтобы понять»: участники, предпосылки, причины, место действия.
6. Для каждой связи — короткое объяснение `why` по-русски (до 15 слов).
7. Ориентир: в среднем 1–3 связи на опорное понятие. У «листьев» (конкретные опыты, приборы, памятники) может быть одна связь, у базовых понятий (масса, сила, государство) связей больше. Если у понятия в каталоге нет пары, оставь список пустым.

## Ответ

Только JSON: по объекту на каждое опорное понятие, в том же порядке.

```json
{"результат": [
  {"id": "C.physics.plotnost-veschestva",
   "связи": [
     {"source": "C.physics.massa", "target": "C.physics.plotnost-veschestva", "type": "prerequisites_for", "why": "плотность определяется через массу и объём"},
     {"source": "C.physics.plotnost-veschestva", "target": "C.physics.fizicheskaya-velichina", "type": "is_a", "why": "плотность — физическая величина"}
   ]}
]}
```
