# План: разбор ошибок моделей и проверка графа

11 октября 2026. Отложено, к реализации — позже. Связано с `МЕТОДИКА — свидетельства и оси.md` (модель свидетельств) и `РЕФЛЕКСИЯ по источникам.md` (Bean 3.7 — анализ ошибок).

## Общий план проекта

1. Доразметить граф на оставшиеся классы (история и физика 5–11).
2. Наполнить узлы знаниями (ЦОК), собрать задания.
3. Прогнать несколько моделей.
4. Сделать выводы и корректировки: по систематическим ошибкам пройти от задания до графа и решить, чья это ошибка — графа, задания или модели.

## Идея

У каждого задания в `basis` записано, из чего оно собрано: ребро графа, id знания с цитатой, формула, шаблон или цепочка. Поэтому путь «неверный ответ → задание → ребро/знание → пункт программы» программа проходит сама. Ошибки моделей становятся проверкой графа: там, где сильные модели систематически расходятся с ключом, вероятнее всего ошибка в графе или в задании, а не в модели.

Это и анализ ошибок по Bean (3.7: «если провалы соответствуют целевому явлению, валидность высока»), и автоматическая проверка графа без ручной вычитки каждого ребра.

## Пять причин неверного ответа

| Причина | Признак | Где искать |
|---|---|---|
| Ошибка графа | Неверное или пропущенное ребро (вид, часть, «нужно знать до», опыт → величина) | `basis.edge`, `basis.prerequisites`, `basis.chain` |
| Ошибка знания | Цитата из ЦОК неточна или вырвана из контекста | `basis.knowledge` → `знания.jsonl` |
| Ошибка сборки задания | Тема урока вместо понятия, двусмысленный неверный вариант, ответ подсказан в вопросе | семейство + текст вариантов; пометки `дистракторы_llm` |
| Ошибка разбора ответа | Модель ответила верно, извлечено не то (формат, единицы, «Ответ:» не в последней строке) | `raw` против `extracted` |
| Ошибка модели | Всё выше в порядке, модель неверна | остаток |

## Решающее правило (чтобы не было круга)

Если все модели ошиблись одинаково, это ещё не значит, что неверен граф: модели учились на похожих данных и могут ошибаться вместе.

1. **Кандидат в ошибку графа/задания:** несколько сильных моделей **разных семейств** сходятся на одном ответе против ключа. Ошибки слабых моделей — шум, сигнал дают ошибки сильных.
2. **Вердикт — проверяющая модель по источнику:** получает задание, ключ, ответ моделей и источник (цитату ЦОК, пункт кодификатора ФОП/ОГЭ, текст элемента). Отвечает: граф / знание / сборка / разбор / модель, с обоснованием.
3. **Человек** смотрит только выборку вердиктов, чтобы оценить точность проверяющего (а не каждый случай). Это число идёт в ВКР как проверка самой процедуры.
4. Подтверждённые ошибки графа → правка (через решения этапов `связи_llm` / `понятия_llm`) и, если повторяется тип ошибки, правка промпта разметки → пересборка.

## Этап «разбор_ошибок» (что написать)

Вход: `задания.jsonl`, прогоны моделей (`прогоны/*.jsonl`), граф среза, знания.

1. **Программа:**
   - собрать матрицу «задание × модель» (верно / неверно / какой ответ);
   - для каждого неверного: восстановить цепочку до графа по `basis`;
   - автоматически отсеять ошибки разбора (в `raw` есть верный ответ в другом формате);
   - найти согласованные ошибки: ≥ 2 сильных моделей разных семейств с одним и тем же неверным ответом;
   - сгруппировать по ребру/знанию: одно ребро → много заданий с ошибками → высокий приоритет (ошибка графа размножается).
2. **LLM (проверяющий):** вердикт по причине для каждого кандидата, по источнику.
3. **Выход:** `4_бенчмарк/<срез>/разбор_ошибок.md` и `.json` — по причинам, со списком подозрительных рёбер и заданий; для графа — файл предлагаемых правок в формате решений этапов.
4. Пилот вердиктов на 7 классе делает Claude (replay), дальше — локальная модель.

## Порядок

- **Сначала прогнать цикл на 7 классе**, до разметки остальных классов. Граф размечала LLM: если в разметке есть системная ошибка (например, темы уроков попадают в «виды»), она повторится во всех классах. Дешевле найти тип ошибки на одном классе и поправить промпт.
- Для 7 класса уже есть один прогон (GigaChat-2-Max). Для правила «≥ 2 сильных моделей» нужны ещё прогоны: GigaChat Lite/Pro (тот же ключ), локальная модель на сервере ПНППК. Скрипт `4_бенчмарк/физика_7/gigachat_bench.py` уже умеет любой OpenAI-совместимый API (`--base-url`).
- Развёрнутые ответы для этого разбора оценивать **другой** моделью, не той, что отвечала (сейчас GigaChat оценивает сам себя).
